Un paso es una llamada del workflow. Los pasos se agregan desde la paleta **Operaciones**, a la izquierda de la pestaña **Diseño**. Cada operación que agregas se vuelve un paso que ya viene completado a partir de su contrato.

## Ejemplo: agrega getPokemon

Arrastra `GET /pokemon/{idOrName}` desde la paleta al lienzo vacío.

<Tabs>
  <TabItem label="En la app">

El lienzo recibe la tarjeta `getPokemon`, con el método **GET** y la ruta `/pokemon/{idOrName}`. Su panel se abre a la derecha. **Inicio** ahora lista el input `idOrName`, y el parámetro lo lee.

![La pestaña Diseño: paleta de operaciones, lienzo con pasos conectados y panel del paso](/media/es/builder.webp)

  </TabItem>
  <TabItem label="En el YAML">

```yaml title="Lo que escribe Luvin" {1,5-6,7-8}
- stepId: getPokemon
  operationId: $sourceDescriptions.pokeapi.getPokemon
  parameters:
    - name: idOrName
      in: path
      value: $inputs.idOrName
  successCriteria:
    - condition: $statusCode == 200
```

  </TabItem>
</Tabs>

## Antes de empezar

La paleta lista las operaciones de los contratos OpenAPI de tu colección. Si dice **La colección no tiene contratos OpenAPI. Agrega uno para ver sus operaciones aquí.**, haz una de estas cosas primero:

- Agrega un contrato. Consulta [Agregar un contrato](/es/contracts/add/).
- Usa los requests que ya tienes. Consulta [Armar desde requests guardados](/es/design/from-requests/).

## Busca una operación

La paleta tiene un grupo por contrato, con su nombre y la cantidad de operaciones que tiene. Cada fila muestra el método, la ruta y el resumen de la operación.

<Steps>
1. Haz clic en el nombre de un grupo para plegarlo o desplegarlo.
2. Escribe en **Buscar operación…** para filtrar. La búsqueda mira la ruta, el id de la operación, el resumen y las etiquetas.
</Steps>

![La paleta Operaciones de la Pokédex: la búsqueda, los workflows de otros archivos Arazzo y las operaciones del contrato pokeapi](/media/es/design-palette.webp)

## Agrégala al workflow

| Cómo | Dónde queda el paso |
|---|---|
| Arrastra la operación al lienzo | Debajo del paso sobre el que la sueltas. Si la sueltas encima del primer paso, queda como el primero. |
| Haz clic en **+** de su fila | Al final del camino feliz: justo después del paso que lo termina con `done`, que pasa al paso nuevo. Sin pasos de rama, es el final del workflow. |
| Haz clic en el **+** de una flecha del lienzo y luego en la operación | Entre las dos tarjetas que une esa flecha. |

Después de agregarlo, el paso nuevo queda seleccionado, su panel se abre a la derecha y el lienzo se desplaza para mantenerlo a la vista.

### Inserta un paso entre otros dos

Cada flecha del lienzo, desde **Inicio** hasta **Fin del workflow**, tiene un **+** en el medio. Su tooltip dice **Insertar un paso aquí**.

<Steps>
1. Haz clic en el **+** de la flecha donde va el paso. Se abre un diálogo con el título **Insertar un paso** y la paleta adentro.
2. Haz clic en una operación, un request o un workflow. Toda la fila se puede pulsar.
</Steps>

El paso queda entre las dos tarjetas. El **+** bajo **Inicio** lo deja como el primer paso; el **+** sobre **Fin del workflow**, como el último. Si el paso de arriba termina el camino feliz con una acción llamada `done`, `done` pasa al paso nuevo, así que el paso nuevo igual se ejecuta.

[Insertar un paso](/es/design/insert-step/) tiene todas las posiciones, el YAML antes y después, y en qué se diferencia insertar de arrastrar. Un diálogo parecido se abre cuando llevas un error a un paso nuevo: mira [Un paso nuevo para un error](/es/design/branch-new-step/).

## Qué recibe automáticamente un paso nuevo

Luvin lee el contrato y completa el paso con reglas. No se adivina nada con IA.

| Parte | Qué pone Luvin |
|---|---|
| Nombre | El id de la operación del contrato, por ejemplo `getPokemon`. Sin id de operación, se arma con el método y la ruta, por ejemplo `getPokemonById`. Si el nombre ya existe, se agrega un número: `getPokemon2`. |
| Descripción | El resumen de la operación, o su método y ruta si no tiene. |
| Criterio de éxito | El menor estado 2xx que documenta el contrato para la operación, por ejemplo 201 en un «crear». Si el contrato no documenta ningún 2xx, 200. |
| Parámetros obligatorios | Cada uno recibe un origen: un paso anterior, un input que el workflow ya tiene o un input nuevo creado para él. Los parámetros opcionales se dejan fuera. |
| Body | Cada campo obligatorio recibe un origen de la misma forma. Si el contrato no marca ningún campo como obligatorio, cada campo simple que no esté en una lista se vuelve un input opcional con el ejemplo del contrato (hasta 25 campos; si son más, ninguno). |

Dos cosas **no** se agregan por ti:

- **Outputs**, salvo los que necesitan las conexiones. Consulta [Outputs](/es/design/outputs/).
- **Acciones ante errores**. El panel del paso lista cada error documentado para que elijas tú. Consulta [Éxito y errores](/es/design/success-and-errors/).

### Un ejemplo

Parte de un workflow vacío en la colección Pokédex.

<Steps>
1. Arrastra `GET /pokemon/{idOrName}` al lienzo. Obtienes el paso `getPokemon`. Nada provee `idOrName` todavía, así que **Inicio** ahora lista un input nuevo, `idOrName`, y el paso lo usa.
2. Arrastra `GET /pokemon-species/{idOrName}` debajo. Obtienes el paso `getPokemonSpecies`. Su `idOrName` muestra `? getPokemon › id`: Luvin lo conectó con el `id` que devuelve el primer paso, y `getPokemon` ahora tiene un output llamado `id`.
</Steps>

La `?` significa que Luvin está menos seguro de esa conexión. [Conectar datos entre pasos](/es/design/wire-data/) explica las reglas y cómo cambiar un origen.

![El workflow después de agregar dos operaciones: Inicio tiene el input nuevo idOrName, getPokemon lo lee y expone id, y una línea de datos baja hasta getPokemonSpecies](/media/es/design-auto-wired.webp)

El panel del paso nuevo se abre enseguida. Su `idOrName` lee el output `id` de `getPokemon`:

![El panel de getPokemonSpecies recién agregado: idOrName sale de id, el éxito es 200 y el 404 todavía no tiene acción](/media/es/design-new-step-panel.webp)

## Otras cosas que puedes agregar

La paleta tiene tres grupos más cuando corresponden. Se agregan igual: arrastrando, o con **+**.

| Grupo | Qué agrega | Lee |
|---|---|---|
| **Requests de la colección** | Un request guardado, enviado tal cual es. | [Armar desde requests guardados](/es/design/from-requests/) |
| **Workflows de este Arazzo** | Otro workflow del mismo archivo, llamado como un paso. | [Workflows que usan otros workflows](/es/design/dependencies/) |
| **Reutilizables** | Una acción de error o un parámetro guardado para usar en varios pasos. Se aplica a un paso, no se agrega como uno. | [Reutilizables](/es/design/reusables/) |

Las operaciones de los contratos AsyncAPI no están en la paleta. [Pasos de mensajería](/es/design/messaging/) explica cómo agregarlas.

![La paleta de un workflow de una tienda: Workflows de este Arazzo, De otros archivos Arazzo y las operaciones del contrato store](/media/es/design-palette-workflows.webp)

### La pregunta sobre los campos obligatorios

Un request guardado no tiene un contrato que diga cuáles de sus campos exige la API. La primera vez que agregas un request a un workflow, un diálogo pregunta **¿Qué exige la API en «…»?** con todos los campos del request.

<Steps>
1. Marca los campos que la API exige. **Marcar todos** y **Ninguno** cambian todos a la vez. Los parámetros de la ruta siempre son obligatorios.
2. Haz clic en **Guardar**, o en **Ahora no** para decidir más tarde.
</Steps>

Tu respuesta se guarda en el request y vale para todos los workflows que lo usen. Las operaciones de un contrato nunca muestran este diálogo: el contrato ya dice qué es obligatorio.

![El diálogo ¿Qué exige la API en «Crear pedido»? con los campos del body customer, marcado como obligatorio, y currency](/media/es/design-required-fields.webp)

## Si el lienzo dice que al workflow le faltan datos

Una barra con el título **A este workflow le faltan datos** aparece cuando un paso usa un input que el workflow no declara, o cuando el contrato pide datos que un paso no envía. Pasa, por ejemplo, después de que un contrato cambia.

Haz clic en **Completar**. Luvin declara los inputs que faltan o conecta los datos con un paso anterior, sin rehacer los pasos. **Deshacer** lo revierte.

![La barra A este workflow le faltan datos sobre el lienzo, con el botón Completar](/media/es/design-gaps-bar.webp)

Ver [Completa los datos que faltan](/es/design/complete-gaps/).
