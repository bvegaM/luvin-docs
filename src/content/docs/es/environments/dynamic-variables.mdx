Una variable dinámica es un `{{nombre}}` que Luvin completa con un valor recién generado: un email nuevo, un UUID nuevo, un documento válido. Úsala cuando un caso se tiene que poder repetir, por ejemplo cuando la API rechaza un email que ya existe. No las defines en el ambiente: siempre están disponibles.

## Ejemplo

Un body para un request "crear cliente", con tres generadores:

```json title="Body del request"
{
  "name": "{{$randomFullName}}",
  "email": "{{$randomEmail}}",
  "externalId": "{{$guid}}"
}
```

Cada ejecución envía valores nuevos. Esta es una ejecución posible:

```json title="Lo que envía una ejecución"
{
  "name": "Daniela Rojas",
  "email": "Daniela.Rojas42@yahoo.com",
  "externalId": "9b2f4c1e-6a37-4d0b-8c55-3e1f7a9d2b64"
}
```

La siguiente ejecución envía otros valores, así que la API nunca ve el mismo email dos veces. Mira la receta [Envía datos generados](/es/recipes/generated-data/).

## Dos familias

| Familia | Se ve así | Cuántas | Referencia |
|---|---|---|---|
| Los generadores propios de Luvin | `{{email}}`, `{{cpf}}`, `{{numero:8}}` | 7, dos de ellos con nombre en español y en inglés | [Los generadores de Luvin](/es/environments/generators/) |
| Variables compatibles con Postman | `{{$randomEmail}}`, `{{$guid}}` | 47 | [Variables compatibles con Postman](/es/environments/postman-variables/) |

Las dos se reemplazan en los mismos lugares y de la misma forma. La diferencia es el nombre: las de `$` son los nombres que usan Postman y Bruno, así que los requests importados siguen funcionando sin cambios. Los generadores propios de Luvin cubren lo que a esas les falta, como un CPF brasileño o un RUT chileno válidos.

## Cómo funcionan

- Escribe el nombre entre llaves dobles, como cualquier [variable](/es/environments/use-variables/): `{{$randomEmail}}`.
- **Cada aparición produce un valor nuevo.** Dos `{{$guid}}` en el mismo body dan dos UUID distintos.
- Se produce un valor nuevo en cada envío y en cada ejecución. Nunca se guarda.
- Los nombres, ciudades, empresas y otros textos de la familia `$` salen en el idioma de la interfaz: español latinoamericano o inglés. Cambia el idioma en **Preferencias** y los valores siguientes lo siguen.
- Cuando escribes `{{` en un campo, Luvin las sugiere. Escribe `{{$` para ver todas las que empiezan con `$`, cada una con un valor de ejemplo. Mira [Sugerencias y colores](/es/environments/suggestions/).
- En un campo se pintan de morado. Pasa el mouse por una y la tarjeta dice *⚡ se genera al ejecutar*.
- Un nombre que no es ni una variable ni un generador, como `{{$randomPet}}`, queda tal como lo escribiste.

## Dónde puedes usarlas

- En la pestaña **Inputs** y en los datos de cada caso, en la pestaña **Casos**.
- En el valor de un parámetro o de un campo del body de un paso, y en el YAML del Arazzo, entre comillas.
- En los requests sueltos: URL, params, headers, body y autorización.
- En las URLs base y las credenciales del ambiente.
- Dentro del valor de una variable del ambiente: una variable `orderRef` con el valor `ORD-{{$randomInt}}` da una referencia nueva cada vez.

Un fragmento real del ejemplo de PayPal, que envía una clave de idempotencia nueva en cada ejecución:

```yaml title="paypal.arazzo.yaml"
requestId:
  name: PayPal-Request-Id
  in: header
  value: '{{$randomUUID}}'
```

## El mismo valor en varios pasos

Cada aparición es nueva, así que dos pasos que escriben `{{$guid}}` envían dos valores distintos. Cuando los pasos siguientes tienen que ver el valor que envió un paso anterior, genéralo una sola vez:

| Dónde escribes el generador | Cada cuánto se genera | Quién ve el mismo valor |
|---|---|---|
| Un parámetro o el body de un paso | En cada envío | Solo ese paso |
| Un input del workflow | Una vez por caso, antes del primer paso | Cada paso que lee `$inputs.nombre` |
| El valor de una variable del ambiente | Cada vez que se usa la variable | Nadie: cada uso es nuevo |

El ejemplo de la Pokédex usa un input: el input `correlationId` de **Register sighting** es `{{$guid}}`, y tanto el paso que publica como el paso que espera usan `$inputs.correlationId`.

Para reutilizar un valor que devolvió la API, como el id del cliente que creó, usa los outputs del paso. Mira [Conectar datos entre pasos](/es/design/wire-data/).

<Aside type="caution" title="Los datos generados son datos reales">
Contra la **API real**, cada ejecución crea registros nuevos con estos valores. Usa un ambiente de pruebas, o un ambiente de mock, cuando un workflow crea clientes u órdenes.
</Aside>
