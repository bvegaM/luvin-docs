Luvin no ejecuta scripts. Cuando importas una colección de Postman o Bruno, lee los scripts que corren después de la respuesta y convierte las líneas comunes (guardar un valor, revisar el status, comparar un campo) en las pestañas **Variables** y **Comprobaciones** de cada request. Lo que no puede convertir en una comprobación queda fuera, y la importación te dice cuánto. Esta página lista cada conversión, para que sepas qué revisar.

## Qué lee Luvin

| De | Qué se convierte | Qué no |
|---|---|---|
| Postman | El script **Tests** de cada request | Los scripts pre-request, y todos los scripts de una carpeta o de la colección |
| Bruno | Los bloques `vars:post-response` y `assert`, y los scripts `tests` y `script:post-response` de cada request, desde la carpeta de archivos `.bru` o desde la exportación `.json` | `script:pre-request`, y los scripts de `folder.bru` y `collection.bru` |

## Ejemplo: un test de Postman

```js
const jsonData = pm.response.json();
pm.environment.set("pokemonId", jsonData.id);
pm.test("Status is 200", function () {
  pm.response.to.have.status(200);
});
pm.test("It is Pikachu", function () {
  pm.expect(jsonData.name).to.eql("pikachu");
  pm.expect(jsonData.types).to.be.an("array");
  pm.expect(pm.response.responseTime).to.be.below(1000);
});
if (jsonData.name !== "pikachu") {
  postman.setNextRequest(null);
}
```

Después de importar, el request tiene:

| Pestaña | Fila |
|---|---|
| **Variables** | `pokemonId` ← `res.body.id` |
| **Comprobaciones** | `res.status` **es igual a** `200` |
| **Comprobaciones** | `res.body.name` **es igual a** `pikachu` |
| **Comprobaciones** | `res.body.types` **es una lista** |
| **Comprobaciones** | `res.responseTime` **es menor que** `1000` |

El bloque `if` se salta completo, y la importación cuenta este script como uno con partes que no se pudieron convertir.

## Importa y revisa

<Steps>

1. Importa la colección: mira [Trae tus propios archivos y requests](/es/get-started/import/).
2. Antes de hacer clic para importar, lee el resumen de cada colección. Dice cuántas variables y comprobaciones se convirtieron y cuántos scripts tenían partes que no (mira [Lo que dice el resumen](#lo-que-dice-el-resumen)).
3. Después de importar, abre un request y mira sus pestañas **Variables** y **Comprobaciones**.
4. Pulsa **Enviar**. Revisa que el chip junto al status diga lo que esperas.
5. Agrega a mano lo que se saltó. Mira [Completa a mano lo que falta](#completa-a-mano-lo-que-falta).

</Steps>

## Guardar variables

| Script | Se convierte en |
|---|---|
| `pm.environment.set("x", …)` | Una variable `x` |
| `pm.collectionVariables.set("x", …)`, `pm.globals.set("x", …)`, `pm.variables.set("x", …)` | Una variable `x` |
| `bru.setVar("x", …)`, `bru.setEnvVar("x", …)` | Una variable `x` |
| Bruno `vars:post-response`: `token: res.body.token` | Una variable `token` |

El segundo argumento tiene que ser algo que Luvin pueda leer de la respuesta (mira la tabla siguiente). Si no, como `jsonData.items.map(i => i.id)`, la línea se salta.

<Aside type="note" title="No se escribe en el ambiente">
En Postman, `pm.environment.set` cambia el ambiente. En Luvin, el valor es un valor guardado: vive en memoria mientras la colección está abierta y gana sobre la variable del ambiente con el mismo nombre. Mira [Guarda valores de una respuesta](/es/requests/save-variables/#en-memoria-no-en-el-ambiente).
</Aside>

## Leer la respuesta

| Script | Se convierte en |
|---|---|
| `pm.response.json().id`, `res.body.id`, `res.getBody().id` | `res.body.id` |
| `jsonData.id`, después de `const jsonData = pm.response.json()` (también con `var` o `let`, `res.getBody()`, `res.body` o `JSON.parse(responseBody)`) | `res.body.id` |
| `res("id")` (Bruno) | `res.body.id` |
| `pm.response.json().items[0].id` | `res.body.items[0].id` |
| `pm.response.json()["user-id"]` | `res.body["user-id"]` |
| `pm.response.code`, `res.status`, `res.getStatus()` | `res.status` |
| `pm.response.responseTime`, `res.responseTime`, `res.getResponseTime()` | `res.responseTime` |
| `pm.response.headers.get("X-Id")`, `res.getHeader("X-Id")`, `res.headers.get("X-Id")`, `res.headers["X-Id"]` | `res.headers.x-id` |

Los nombres de los headers pasan a minúsculas. Los índices negativos (`[-1]`) y las llamadas a métodos (`.map()`, `.find()`, `.filter()`) no se convierten.

## Comprobar la respuesta

### Comprobaciones de toda la respuesta (Postman)

| Script | Se convierte en |
|---|---|
| `pm.response.to.have.status(201)` | `res.status` **es igual a** `201` |
| `pm.response.to.be.ok`, `pm.response.to.be.success` | Dos comprobaciones: `res.status` **es mayor o igual a** `200` y **es menor que** `300` |
| `pm.response.to.have.header("X-Id")` | `res.headers.x-id` **existe** |
| `pm.response.to.be.json` | `res.headers.content-type` **contiene** `json` |

### expect

`pm.expect(…)` (Postman) y `expect(…)` (Bruno) se convierten en una comprobación cada uno, cuando lo que está entre paréntesis es algo que Luvin puede leer de la respuesta:

| Cadena | Comprobación |
|---|---|
| `.to.eql(x)`, `.to.equal(x)`, `.to.eq(x)`, `.to.equals(x)`, `.to.deep.equal(x)` | **es igual a** |
| `.to.not.eql(x)`, `.to.not.equal(x)` | **no es igual a** |
| `.to.be.above(x)`, `.to.be.greaterThan(x)`, `.to.be.gt(x)` | **es mayor que** |
| `.to.be.at.least(x)`, `.to.be.gte(x)` | **es mayor o igual a** |
| `.to.be.below(x)`, `.to.be.lessThan(x)`, `.to.be.lt(x)` | **es menor que** |
| `.to.be.at.most(x)`, `.to.be.lte(x)` | **es menor o igual a** |
| `.to.include(x)`, `.to.contain(x)`, `.to.contains(x)`, `.to.have.string(x)` | **contiene** |
| `.to.not.include(x)`, `.to.not.contain(x)` | **no contiene** |
| `.to.match(/…/)` | **coincide con (regex)**, con el patrón y sus opciones |
| `.to.exist`, `.to.not.be.undefined` | **existe** |
| `.to.be.ok` | **es verdadero** |
| `.to.not.exist`, `.to.be.undefined` | **no existe** |
| `.to.be.null` | **es null** |
| `.to.be.empty` | **está vacío** |
| `.to.not.be.empty` | **no está vacío** |
| `.to.be.a("string")`, `.to.be.an("string")` | **es texto** |
| `.to.be.a("number")` | **es número** |
| `.to.be.a("boolean")` | **es true/false** |
| `.to.be.an("array")` | **es una lista** |
| `.to.be.an("object")` | **es un objeto** |

<Aside type="note">
En Postman, `.to.be.ok` significa "es verdadero": no es `0`, `""`, `false` ni `null`. Luvin lo convierte en **es verdadero**, que pasa y falla con los mismos valores. Solo `pm.response.to.be.ok`, sobre la respuesta entera, se convierte en las dos comprobaciones de status de arriba.
</Aside>

### El valor esperado

La `x` de la cadena tiene que estar escrita como un valor:

| En el script | Valor esperado en Luvin |
|---|---|
| `200`, `-1`, `3.5` | `200`, `-1`, `3.5` |
| `true`, `false`, `null` | `true`, `false`, `null` |
| `"pikachu"`, `'pikachu'`, `` `pikachu` `` | `pikachu` |
| `[1, 2]`, `{ 'id': 7 }` | `[1,2]`, `{"id":7}` |

Una variable o una expresión como valor esperado, como `pm.environment.get("id")` o `` `order-${id}` ``, no se puede convertir: la línea se salta. Escríbela en Luvin con una `{{variable}}`: `{{id}}`.

### assert de Bruno

Cada línea del bloque `assert` se convierte en una comprobación. El nombre del operador tiene que ser uno de los [nombres del archivo](/es/requests/check-operators/#todas-las-comprobaciones) de Luvin, que son los mismos de Bruno:

```
assert {
  res.status: eq 200
  res.body.name: isString
  res.body.types: isNotEmpty
  ~res.body.order: gt 0
}
```

| Línea | Se convierte en |
|---|---|
| `res.status: eq 200` | `res.status` **es igual a** `200` |
| `res.body.name: isString` | `res.body.name` **es texto** |
| `res.body.types: isNotEmpty` | `res.body.types` **no está vacío** |
| `~res.body.order: gt 0` (desactivada en Bruno) | `res.body.order` **es mayor que** `0`, desmarcada |

Un operador que Luvin no tiene, como `between`, se salta.

## Qué se salta y por qué

| Se salta | Por qué |
|---|---|
| Los scripts pre-request | Corren antes del request y pueden cambiarlo. Luvin no ejecuta código. Usa en cambio las [variables del ambiente](/es/environments/variables-and-secrets/), las [variables dinámicas](/es/environments/dynamic-variables/) y la [autorización](/es/authorization/overview/) del request. |
| Los scripts de una carpeta o de la colección | Luvin guarda las comprobaciones por request. |
| Todo lo que está dentro de `if`, `else`, `for`, `while`, `switch`, `try`, `catch`, `finally` o `do` | Una comprobación que solo tenía sentido con una condición ("si es un 404, el error dice…") fallaría con cada `200`. Se salta el bloque completo, también sus líneas de cierre. |
| Las líneas que Luvin no reconoce | Por ejemplo `pm.expect(jsonData).to.have.property("id")`, `.to.have.lengthOf(3)`, `.to.be.true`, `.to.be.oneOf([200, 201])`, `postman.setNextRequest(…)`, `console.log(…)`, o código que firma o calcula valores. |
| Un mensaje como segundo argumento | `pm.expect(jsonData.id, "has an id")` no se convierte. |

Los comentarios (`//` y `/* … */`) y los envoltorios `pm.test("…", function () {` y `});` se ignoran: no cuentan como saltados.

## Completa a mano lo que falta

| En el script | En Luvin |
|---|---|
| `pm.expect(jsonData).to.have.property("id")` | `res.body.id` **existe** |
| `pm.expect(jsonData.items).to.have.lengthOf(3)` | `res.body.items.length` **es igual a** `3` |
| `pm.expect(jsonData.active).to.be.true` | `res.body.active` **es igual a** `true` |
| `pm.expect(pm.response.code).to.be.oneOf([200, 201])` | `res.status` **es mayor o igual a** `200` y `res.status` **es menor o igual a** `201` |
| `pm.expect(jsonData.id).to.eql(pm.environment.get("orderId"))` | `res.body.id` **es igual a** `{{orderId}}` |
| Una comprobación dentro de `if (pm.response.code === 404)` | Un request aparte para ese caso, con `res.status` **es igual a** `404` y sus propias comprobaciones |

## Lo que dice el resumen

El resumen de cada colección, antes de importar, dice:

- *N variable(s) y comprobación(es) convertidas de los scripts (pestañas Variables y Comprobaciones de cada request).*
- *N script(s) tienen partes que no se pudieron convertir (pre-request o lógica en JavaScript): no se importan, porque Luvin no ejecuta scripts. Lo común (guardar una variable, revisar el status o un campo) sí se convirtió.*

![El paso de revisión de Importar de Postman o Bruno para una colección Shop API: 3 requests, 1 carpeta, 0 ejemplos, 1 ambiente, 8 variable(s) y comprobación(es) convertidas de los scripts, y un aviso de que 2 script(s) tienen partes que no se pudieron convertir](/media/es/import-checks-summary.webp)

El segundo número cuenta scripts, no líneas:

| Colección | Qué cuenta como uno |
|---|---|
| Postman | Cada script pre-request, cada script **Tests** con al menos una línea saltada, y cada script de una carpeta o de la colección |
| Bruno, carpeta de archivos `.bru` | Cada `script:pre-request`, cada script `tests` o `script:post-response` con una línea saltada, los bloques `vars:post-response` y `assert` de un request (una vez por los dos) cuando se saltó una línea, y cada script de `collection.bru` |
| Bruno, exportación `.json` | Cada request con un script pre-request o con una línea saltada, una vez |

Los scripts de un `folder.bru` de Bruno no se convierten ni se cuentan.
