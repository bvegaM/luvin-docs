Cuando un paso devuelve una lista y un paso siguiente necesita un elemento de ella, una ejecución a mano se detiene y te pregunta cuál. El runner nunca pregunta: no hay nadie mirando. Usa la regla guardada en el paso, o el elemento al que apunta el diseño. Esta página dice qué elige cada regla en una ejecución del runner y cómo manejar las reglas desde ahí.

## Ejemplo: el tipo y la habilidad de Pokemon card

En **Pokemon card**, el paso `getPokemon` devuelve dos listas, `types` y `abilities`. Los pasos siguientes leen un elemento de cada una por su posición: `$response.body#/types/0/type/name` y `$response.body#/abilities/0/ability/name`. Para `abilities` guardaste la regla **El que cumpla…** `ability.name` **es** `lightning-rod` desde el diálogo de la lista.

<Steps>
1. Abre el runner para `pokemon.arazzo.yaml` con **Ejecutar workflows (runner)**.
2. En **Listas en las respuestas**, lee las dos líneas:
   - **Pokemon card** · `getPokemon` types, *El elemento 1 (el que dice el diseño)*.
   - **Pokemon card** · `getPokemon` abilities, *el que cumpla ability.name es lightning-rod*, con **Quitar**.
3. Pulsa **Ejecutar (n casos)**.
</Steps>

En cada vuelta, la ejecución sigue con el tipo `electric` y la habilidad `lightning-rod`. El paso guarda una nota de lo que eligió. Mira [Qué queda registrado](/es/test/lists/#qué-queda-registrado).

## Qué elige cada regla en el runner

| Regla guardada | Qué hace el runner |
|---|---|
| Sin regla | Usa el elemento que dice el diseño. |
| **Preguntarme** | Usa el elemento que dice el diseño: no hay a quién preguntar. |
| **Usar el que dice el diseño** | Usa el elemento que dice el diseño. |
| **Elegir uno al azar** | Cualquier elemento, elegido otra vez cada vez que el paso se ejecuta. |
| **Uno distinto en cada vuelta** | El primer elemento en la vuelta 1, el segundo en la vuelta 2, y así. Cuando la lista es más corta que las vueltas, vuelve a empezar: con 3 elementos, la vuelta 4 usa el primero. |
| **El que cumpla…** | El primer elemento que cumple la condición. Si ninguno la cumple, el paso falla. Mira [Cuando ningún elemento cumple](#cuando-ningún-elemento-cumple). |
| **Todos** | Toda la lista, cuando los pasos siguientes pueden recibir varios elementos. Si reciben un solo valor, el elemento que dice el diseño. |

En una prueba de rendimiento, **Uno distinto en cada vuelta** cuenta las vueltas de cada usuario virtual: cada usuario empieza con el primer elemento. Mira [Rendimiento de workflows](/es/runner/performance-workflows/).

## Las condiciones de «El que cumpla…»

| Condición | Cumple cuando el campo… | Ejemplo |
|---|---|---|
| **es** | Es exactamente el valor, como texto. | `status` **es** `ACTIVE` |
| **no es** | Es cualquier otra cosa, incluso si falta. | `status` **no es** `BLOCKED` |
| **contiene** | Contiene el valor, sin importar mayúsculas o minúsculas. | `name` **contiene** `pika` cumple con `Pikachu` |
| **es mayor que** | Es un número mayor que el valor. | `stock` **es mayor que** `0` |
| **es menor que** | Es un número menor que el valor. | `price` **es menor que** `100` |

- El campo puede estar dentro de un objeto, con puntos: `address.city`.
- **es mayor que** y **es menor que** comparan números. Un campo vacío o que no es un número nunca cumple.
- **es** compara texto: `25` cumple con el número 25, pero `25.0` no.

## La sección Listas en las respuestas

**Listas en las respuestas** está en la configuración del runner de workflows, bajo **Datos por vuelta**. Aparece con los dos valores de **Tipo de ejecución**: **Funcional** y **Rendimiento**. Para cada workflow marcado, lista:

- Cada lista de la respuesta de un paso que los pasos siguientes leen por su posición, con un output como `$response.body#/types/0/type/name`.
- Cada lista con una regla guardada en el paso.

En el runner nadie elige, así que cada línea dice con qué elemento sigue la ejecución. Cada línea tiene:

| Parte | Ejemplo |
|---|---|
| El workflow, en negrita | **Pokemon card** |
| El paso | `getPokemon` |
| La lista: la última parte de su ruta, o *la respuesta* cuando la respuesta entera es la lista | `types`, `abilities` |
| El elemento con que sigue la ejecución: la regla guardada o, sin regla, el que dice el diseño | *El elemento 1 (el que dice el diseño)*, *el que cumpla ability.name es lightning-rod*, *Elegir uno al azar*… |
| **Quitar**, solo junto a una regla guardada | Borra la regla. |

El número de *El elemento N (el que dice el diseño)* es la posición del output más uno: `types/0` es *El elemento 1*.

La pista sobre las líneas depende del tipo de ejecución:

| Tipo de ejecución | Pista |
|---|---|
| **Funcional** | *Aquí nadie elige: en cada vuelta, el paso sigue con este elemento de su lista. Para cambiarlo, ejecuta el workflow y guarda una regla desde la pausa.* |
| **Rendimiento** | *En la prueba de carga nadie elige: cada usuario, en cada vuelta, sigue con este elemento de la lista que le devuelve el paso. Para cambiarlo, ejecuta el workflow y guarda una regla desde la pausa.* |

Un workflow sin marcar, o sin casos que ejecutar, no muestra sus listas. Sin ninguna lista, la sección dice *Ningún paso devuelve una lista que usen los pasos siguientes.*

Después de una prueba de rendimiento, los resultados cuentan con qué elementos siguió cada lista. Mira [Elementos usados de las listas](/es/runner/performance-results/#elementos-usados-de-las-listas).

## Guarda una regla

Las reglas se guardan desde el diálogo de la lista, cuando ejecutas un workflow a mano:

<Steps>
1. Ejecuta un caso del workflow con **Ejecutar**. El diálogo se abre después del paso que devuelve la lista.
2. Abre **Las próximas veces:** y elige la regla.
3. Elige el elemento para esta ejecución y continúa.
</Steps>

![La parte de abajo del diálogo de la lista con la lista Las próximas veces: abierta: Preguntarme, Usar el que dice el diseño, Elegir uno al azar, Uno distinto en cada vuelta y El que cumpla…](/media/es/list-pick-rule.webp)

La regla se guarda en el paso del archivo Arazzo, bajo `x-luvin-pick`. Mira [Reglas para las próximas veces](/es/test/lists/#reglas-para-las-próximas-veces).

## Quita una regla

<Steps>
1. En **Listas en las respuestas**, busca la línea de la regla.
2. Pulsa **Quitar**. Solo aparece en una línea con una regla guardada.
</Steps>

La regla se borra del archivo Arazzo. Si el diseño lee esa lista por posición, la línea queda y muestra el elemento que dice el diseño, por ejemplo *El elemento 1 (el que dice el diseño)*. Si no, la línea desaparece. Desde ahí, el runner usa el elemento que dice el diseño para esa lista, y una ejecución a mano te vuelve a preguntar.

## Cuando ningún elemento cumple

Si ningún elemento cumple la condición de **El que cumpla…**, el runner no sigue con otro elemento como si nada. El paso falla con un mensaje como:

*Ningún elemento de la lista (3) cumple la regla: bank es Banco Sur.*

- El caso falla, así que el workflow falla en esa vuelta.
- Con **Detenerse si un workflow falla** marcado, la ejecución termina ahí con **Se detuvo en un error**.
- En una prueba de rendimiento, cuenta como un error de ese paso. El paso sí respondió, así que la pestaña **Errores** muestra su status, por ejemplo `200`, como motivo.

Qué hacer:

| Causa | Arreglo |
|---|---|
| Los datos cambiaron: en este ambiente no hay una tarjeta de ese banco. | Usa datos que la tengan, o cambia el valor de la regla. |
| El nombre del campo está mal, o está dentro de un objeto. | Abre la respuesta del paso y revisa el campo, por ejemplo `address.city`. |
| Comparaste un número con **es**. | Usa el texto exacto del valor, o **es mayor que** / **es menor que**. |
| Cualquier elemento sirve. | Guarda **Usar el que dice el diseño** o **Elegir uno al azar** en su lugar. |
