A dynamic variable is a `{{name}}` that Luvin fills with a freshly generated value: a new email, a new UUID, a valid tax ID. Use one when a case must be repeatable, for example when the API rejects an email that already exists. You do not define them in the environment: they are always there.

## Example

A body for a "create customer" request, with three generators:

```json title="Request body"
{
  "name": "{{$randomFullName}}",
  "email": "{{$randomEmail}}",
  "externalId": "{{$guid}}"
}
```

Each run sends new values. This is one possible run:

```json title="What one run sends"
{
  "name": "Daniela Rojas",
  "email": "Daniela.Rojas42@yahoo.com",
  "externalId": "9b2f4c1e-6a37-4d0b-8c55-3e1f7a9d2b64"
}
```

The next run sends other values, so the API never sees the same email twice. See the recipe [Send generated data](/recipes/generated-data/).

## Two families

| Family | Looks like | How many | Reference |
|---|---|---|---|
| Luvin's own generators | `{{email}}`, `{{cpf}}`, `{{number:8}}` | 7, with Spanish and English names for two of them | [Luvin's generators](/environments/generators/) |
| Postman-compatible variables | `{{$randomEmail}}`, `{{$guid}}` | 47 | [Postman-compatible variables](/environments/postman-variables/) |

Both are replaced in the same places and the same way. The difference is the name: the `$` ones are the names Postman and Bruno use, so imported requests keep working without changes. Luvin's own ones cover what those lack, such as a valid Brazilian CPF or Chilean RUT.

## How they work

- Write the name between double braces, like any [variable](/environments/use-variables/): `{{$randomEmail}}`.
- **Every occurrence produces a new value.** Two `{{$guid}}` in the same body give two different UUIDs.
- A new value is produced on every send and every run, never stored.
- Names, cities, companies and other texts of the `$` family come out in the language of the interface: English, or Latin American Spanish. Change the language in **Preferences** and the next values follow it.
- When you type `{{` in a field, Luvin suggests them. Type `{{$` to see all the `$` ones, each with an example value. See [Suggestions and colors](/environments/suggestions/).
- In a field, they show in purple. Point at one and the card says *⚡ is generated when running*.
- A name that is neither a variable nor a generator, such as `{{$randomPet}}`, is left as written.

## Where you can use them

- In the **Inputs** tab and in the data of each case, in the **Cases** tab.
- In the value of a parameter or of a body field of a step, and in the Arazzo YAML, in quotes.
- In single requests: URL, params, headers, body and authorization.
- In the base URLs and credentials of the environment.
- Inside the value of an environment variable: a variable `orderRef` with the value `ORD-{{$randomInt}}` gives a new reference every time.

A real fragment from the PayPal example, which sends a new idempotency key on every run:

```yaml title="paypal.arazzo.yaml"
requestId:
  name: PayPal-Request-Id
  in: header
  value: '{{$randomUUID}}'
```

## The same value in several steps

Each occurrence is new, so two steps that write `{{$guid}}` send two different values. When later steps must see the value an earlier step sent, generate it once:

| Where you write the generator | How often it is generated | Who sees the same value |
|---|---|---|
| A step's parameter or body | On every send | Only that step |
| An input of the workflow | Once per case, before the first step | Every step that reads `$inputs.name` |
| The value of an environment variable | Every time the variable is used | Nobody: each use is new |

The Pokédex example uses an input: the `correlationId` input of **Register sighting** is `{{$guid}}`, and both the step that publishes and the step that waits use `$inputs.correlationId`.

To reuse a value an API returned, such as the id of the customer it created, use the step's outputs instead. See [Connect data between steps](/design/wire-data/).

<Aside type="caution" title="Generated data is real data">
Against the **Real API**, every run creates new records with these values. Use a test environment, or a mock environment, when a workflow creates customers or orders.
</Aside>
